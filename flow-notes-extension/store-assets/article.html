How HTTP caching actually works

A plain guide · 8 min read

Every response a server sends can carry instructions about how long a browser may keep it. Get them right and repeat visits feel instant; get them wrong and users see stale pages, or download the same file again and again.

The most common instruction is Cache-Control. A response with max-age=3600 can be reused for an hour without asking the server again. After that it is considered stale, but stale does not mean useless.

A stale response can be revalidated. The browser sends the ETag it stored earlier, and if nothing changed the server answers 304 Not Modified with no body at all, which costs a round trip but almost no bandwidth.

The most misunderstood directive is no-cache, which does not mean what it says.
